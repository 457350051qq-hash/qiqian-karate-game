# 七千武道 · V0.3 净心道场

面向 iPhone、iPad 横屏及电脑浏览器的 2D 卡通空手道街机游戏。延续 V0.1/V0.2 的角色选择、八方向攻击、20 个通关、3 次失守失败、音效、重开及可选摇晃跳跃；现在可以在中央区域移动，使用四种有独立时序的拳脚技术。

无需构建、注册、第三方依赖或付费服务。没有卷轴镜头，不修改仓库公开权限。

## 怎样试玩

在 Mac/电脑下载完整仓库并解压，Chrome 打开 `index.html` 即可。保留全部文件及相对路径，不能只下载 HTML。手机、iPad 适合横屏；竖屏会提示旋转并暂停，当前进度保留。

- **移动、瞄准**：左侧自由摇杆；电脑用 WASD 或方向键，斜向可同时按两个方向键。松开停止移动，保留最后攻击朝向。
- **攻击**：右侧「击」或空格，每次按下出一招，长按不会连发。朝向是八方向；出招后锁定本次方向，恢复结束前不能重复攻击。
- **跳跃**：右侧「跳」或 J；支持同时移动、攻击、跳跃。空中不能再次跳跃。
- **暂停**：顶部「暂停」。打开设置、页面失焦、切到后台、手机竖屏时也会暂停。返回可继续；手动暂停需要点「继续」。
- **重新开始 / 换角色**：底部按钮。男女角色能力完全相同。

第一关击碎 **20** 个病菌通关；病菌贴身或扫杆撞中造成一次「失守」，共 **3** 次失败。短暂受击缓冲避免同一瞬间叠加多次失守。

### 四种招式如何出现

不随机抽取招式；攻击时根据面向扇区内敌人的距离、偏角及数量选择，角色移动受动作恢复限制。

| 招式 | 自动选择的典型条件 | 准备/发力 → 命中窗 → 收招 | 最大地面判定距离 |
| --- | --- | --- | --- |
| 顺突 Oi-zuki | 近身约 110 以内 | 0.09 → 0.10 → 0.19 秒 | 142 |
| 逆突 Gyaku-zuki | 正面中近距离，约 110–165 | 0.15 → 0.11 → 0.25 秒 | 177 |
| 前蹴 Mae-geri | 较远、单一正面目标；或空中无近身目标 | 0.18 → 0.13 → 0.25 秒 | 235 |
| 回蹴 Mawashi-geri | 较远目标偏向扇区边缘，或可覆盖多个目标 | 0.22 → 0.13 → 0.29 秒 | 216 |

判定单位基于 960×540 逻辑场景，随屏幕缩放。以上是游戏化平衡值，不是教学标准。攻击只在命中窗有效；出招到命中时敌人仍可能移动，所以需要预判。回蹴扇区较宽、顺突启动较快。无目标时默认顺突；攻击范围在地面以淡色扇区提示。

动画分为准备、发力、命中、收招。顺突表现同侧步拳配合，逆突有肩髋转动，前蹴先提膝再伸腿、收腿，回蹴包含支撑脚转动及髋膝弧线。当前为可替换的程序化分层动画原型，仍需空手道教练和动画师进一步校正，不是动作教学。

### 敌人与跳跃的用途

- **绿 · 普通病菌**：持续接近玩家，身体攻击不会因玩家跳起就自动失效。
- **橙 · 快速病菌**：较小、速度更快，低位接触在跳起足够高度时可避开；仍会追踪，落地后需处理。
- **紫 · 跳跃病菌**：周期性跃起、落地，速度节奏变化；能越过扫杆。高处病菌避开地面拳击，空中攻击或腿法可拦截。其接触仍能伤到跳跃玩家。
- **地面扫杆**：首次约第 9 秒出现，先预警 1.6 秒，再从左向右横扫。扫杆接近脚下时跳跃可避开；不用担心血腥表现。移动能调整相遇时机，无法在中央边界内永远躲开。

人物活动范围为中央约 24% 场景宽、24% 场景高。敌人持续追踪，不会因为人物离开初始中心就自行漏掉。敌人最多同时 5 个，随击败数逐步加快、缩短间隔，快速和跳跃类型在击败 3 个后加入。

## iPhone Safari 摇晃跳跃（可选实验）

在「设置」点击「开启摇晃跳跃」，若 Safari 弹出运动权限提示，选择允许。默认关闭；拒绝授权或无读数时，屏幕跳跃键和 J 仍可用。

需要 **HTTPS 安全上下文**、传感器及浏览器权限。现有 GitHub Pages 是 HTTPS；普通 `http://局域网IP:8000` 通常无法在 iPhone 上授权传感器。当前项目不会自动申请权限或依赖传感器才能游玩。

力度阈值默认 **16 m/s²**，可调 **8–30**，越低越灵敏，触发冷却 **1.2 秒**。优先使用无重力加速度，否则使用相邻含重力读数的变化量。可随时关闭。握稳手机轻试，无需猛烈摇晃。

## 本地开发与手机试玩

如果有 Python 3，在项目文件夹运行：

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

电脑打开 `http://localhost:8000`。手机连接同一可信 Wi-Fi，访问 `http://你的电脑局域网IP:8000`，必要时允许本机防火墙连接。此方式可以测试摇杆和跳跃键，但 iPhone 的摇晃权限仍需要可信 HTTPS。终端 Control+C 停止服务。

## 文件结构与性能

- `index.html`：道场界面、角色选择、操作键、旋转提示和运动设置。
- `style.css`：横屏网格、刘海安全区、平板和桌面布局；操作区域与画布分列。
- `game.js`：保留原有输入/传感器辅助函数，负责键盘、三指触控、暂停、声音与界面。
- `arcade.js`：纯战斗模拟、移动边界、招式数据/阶段、敌人追踪、伤害、扫杆和胜负。
- `renderer.js`：道场缓存背景、角色分层关节姿态、男女脸部/发型、道服/腰带、病菌与反馈。
- `tests/core.test.js`：保留的 V0.1/V0.2 辅助函数回归测试。
- `tests/arcade.test.js`：V0.3 战斗及分层动作测试。
- `tests/browser-smoke.mjs` / `tests/cdp.mjs`：无依赖浏览器集成测试与 CDP 客户端。

仍是原项目的原生 Canvas 架构，只将新增战斗和绘制独立成文件，方便替换美术、扩展关卡和动作。按 `arcade.js → renderer.js → game.js` 的顺序加载，均为相对路径，不使用 CDN、远程字体、动态导入或服务器 API。静态子路径和本地文件可用。

战斗使用 120Hz 固定时间步与 requestAnimationFrame 绘制；页面卡顿时限制累计追赶，后台暂停。Canvas 像素密度上限 2；背景缓存绘制；敌人数与击退对象有上限，使用原地压缩回收列表；没有大量粒子或外部动画库。实际帧率、热量和 Safari 设备差异仍需真机测试。

## 测试

Node.js 18+ 可执行语法与逻辑检查：

```sh
node --check game.js
node --check arcade.js
node --check renderer.js
node --test tests/*.test.js
```

可选浏览器集成测试需要 **Node.js 22+**（原生 WebSocket）与 Chromium/Chrome。先启动静态服务，再在单独终端启动专用测试浏览器：

```sh
chromium --headless --disable-gpu --remote-debugging-port=9222 --user-data-dir=/tmp/qiqian-browser-test about:blank
node tests/browser-smoke.mjs
```

Mac 可用 `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"` 替换 `chromium`。请使用临时测试用户目录，不要连接存有个人数据的日常浏览器。结束后关闭测试浏览器和本地服务。

可设置 `CDP_PORT`、`TEST_URL` 适应其他端口或 Pages 子路径，例如：

```sh
CDP_PORT=9225 TEST_URL=http://localhost:8014/qiqian-karate-game/ node tests/browser-smoke.mjs
```

集成测试只在测试页面模拟时钟、随机种子与运动权限接口；通过真实 DOM、Canvas、键盘事件与 CDP 三指触控运行原游戏逻辑。包含 WASD/斜向移动、操作释放、失焦、竖屏暂停/恢复、四种横屏尺寸、运动授权拒绝/允许、三种跳跃入口、失败与键盘驱动 20 击通关。真实 requestAnimationFrame 启动与渲染另做浏览器运行检查。

V0.3 已通过 16 项逻辑/姿态测试，以及 Chromium 集成检查。667×375、844×390、1024×768、1366×768 布局通过，控制键不遮挡画布且没有页面滚动。已在本地模拟 `/qiqian-karate-game/` 子路径验证资源加载。

**未进行真实 iPhone / iPad Safari 测试。** 模拟触控与权限不代表真实传感器、Safari 音频恢复、安全区和设备性能已经验证。当前云网络对 GitHub Pages 站点及 GitHub API 返回 Forbidden，不能声称已验证线上 Pages 部署成功。

## 如何发布到现有 GitHub Pages

V0.3 开发分支为 `feature/qiqian-v0.3-cartoon-arcade`。分支推送本身不会自动更新现有 `main` 版网站，也没有创建额外公开预览。

1. 创建以 `main` 为目标的 Pull Request，查看代码与测试结果。
2. 由仓库所有者确认并合并，勿自动合并。
3. 若 Pages 仍按现有 `main` 根目录发布，等待 GitHub 完成 Pages 构建/部署；可在仓库 Actions 或 Settings → Pages 查看状态。项目无新增构建步骤或仓库可见性修改。
4. Safari/Chrome 打开现有网站 `https://457350051qq-hash.github.io/qiqian-karate-game/`。看到顶栏 **V0.3** 即为新版；如缓存旧版，请刷新或重新打开页面。

发布前仍需实际核实仓库当前 Pages 设置；本任务不修改它。API 权限不足时可通过 GitHub 网页手动创建 PR，不应提供令牌到聊天中。

本版有实质性的角色比例、轮廓、关节动作、移动和战斗更新，已能完整游玩；视觉仍是 **分层程序化卡通原型**，没有声称达到正式商业动画素材质量。待机整理腰带、失衡、连击表情、受击、合掌/行礼庆祝均为初步实现；病菌击退、45ms 停顿与轻微镜头震动也已加入。
